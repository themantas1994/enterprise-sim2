# Source ledger

Every Star Trek value (number, component name, behaviour) and every engine or platform fact used by the
project is recorded here with an official source and is referenced elsewhere by its `id`.
Code, ship data and tests cite ledger ids (for example `D-WARP-004`) instead of repeating the source.

## Rules

The single source of truth is *Star Trek: The Next Generation Technical Manual* (Sternbach and Okuda, Pocket
Books, 1991), as set out in `docs/PLAN.md` section 1. In order:

1. Every Star Trek value (a number, a component name, a behaviour, a procedure) comes from the manual and is
   recorded here with its section and book page. Where the manual gives a value it wins over any other source,
   including dialogue and earlier ledger rows.
2. Where the manual is silent, an on-screen TNG episode (named, with the scene) may be used only for scenario
   flavour. Such rows say "not in the manual" in `meaning`. The episode rows were read from public fan-made
   dialogue transcripts as a reading aid (the episodes were not re-viewed, so there are no timestamps).
3. Values that are not Star Trek facts (heat rates, countdown lengths, damage per hit, conduit losses the manual
   does not give, UI scales) are `estimate` game-tuning rows. Each says why it exists and never contradicts the
   manual.
4. A value the manual should hold but the OCR text cannot read is checked against the page image. If it is still
   unreadable it stays `unverified` and is not used.
5. Engine and platform facts (`ENG-*` rows): the vendor's own documentation for the exact version.
6. Paraphrase only. Never copy book text, tables, diagrams or artwork into the repository.

Conventions:

- `id` format: `D-<SYSTEM>-<NNN>` for ship values and `ENG-<TOPIC>-<NNN>` for engine and platform facts. Code,
  ship data and tests cite ids (for example `D-WARP-004`) instead of repeating the source.
- `section/scene`: manual section and book page (book page is about the PDF page minus 10; the printed number
  is used). Episode rows give the scene.
- `status`: `verified` (checked against the cited source; manual numbers on the page image), `estimate`
  (game-tuning constant only), `unverified` (recorded, not yet checked, not used).
- A manual section that was read and states no figure for a quantity is recorded as a `verified` row whose
  value is "not stated" (with the section read). The game-scale number that then has to exist is a separate
  `estimate` row.
- `verified_by`: who or what checked the value against the source, and how.
